# Tweet bookmarklet

Entry: Tools → Bookmarklets → Tweet, in either window mode.
Installation: Replace an existing saved Tweet bookmarklet with the current button/link or copied one-line code. Saved bookmarklets contain their own capture code; updating the site cannot rewrite them.
Capture: Text, author and tweet link, plus the first attached still photo from the selected tweet. The declared page rendition is used; original-resolution capture is not promised. If nothing is selected, the permalink tweet or first visible tweet is used. Additional photos remain source links in the draft.
Review: The first photo appears in the ordinary attachment preview. Remove or replace it before pressing Post. Publication uses the existing approved-member, signed-image rules and image-content feature setting.
Recovery: Pending or failed import keeps the draft and blocks silent text-only publication. If the import script itself cannot load, an inline guard keeps the draft/attachment intent and offers manual attachment or explicit removal without reloading away edits. Retry, download from Photo source and attach manually, or choose Remove photo to proceed with text. Outbox cannot save an expected/attached image. Importing into a disabled/ineligible image flow provides recovery rather than bypassing eligibility.
Reload: Source links and the import fragment permit reattachment; this does not add binary attachment persistence. Explicit removal/replacement clears import intent so it will not restart on reload. Existing draft precedence still applies: explicit bookmarklet text prefill takes precedence over a stored composer text draft.
Limits: One locally saved photo; no gallery, photo picker, quote media, video, animated import or automatic publication. The public image host and source-page browser policy can block capture. Old browsers unable to import can use the photo source and ordinary manual attachment when supported.

## Developer contract

Handoff: /compose/thread keeps its existing subject/body query prefill; #tweet-image=<percent-encoded HTTPS photo URL> is client-only import intent, not a server fetch parameter.
Trust boundary: The browser adapter accepts only pbs.twimg.com/media/ still-image URLs, rejects credential-bearing/foreign URLs and redirects, omits credentials/referrer, times downloads out at 15 seconds and caps input at 32 MiB before existing preparation/validation. No server URL fetch or proxy is added.
Initialization: A synchronous fingerprinted script before composer markup defines the adapter. Parser-time binding establishes visible pending state and submission protection before primary actions can paint; the server HTML is viewer-independent. Later updates reflect download/preparation/eligibility changes.
Reuse: ForumImagePrepare, ForumImageUpload, canonical composer controls and existing signed prepared-post publication. Pending/failed import participates in uploader.has; native/anonymous and Outbox capture protection also works before signing or when image support is disabled.
Lifecycle: Removal, replacement or discard invalidates the previous attempt and aborts its request; late data cannot overwrite a newer attachment. Text fields are never replaced by the importer. No schema, record, API publication or membership changes.
Assets: New script uses normal AssetFingerprint serving; rebuild/invalidate public artifacts through the ordinary deployment path. The existing shared-release entry is `php scripts/refresh_static_shared_artifacts.php <repository> <database> <static-root>`; verify configured paths before running it. Single-route lazy building preserves existing artifacts and is not a refresh command. Existing static Bookmarklets artifacts may retain their old fingerprint until regenerated; verify the rebuilt page before telling users to reinstall. No deployment performed by this cycle.
Checks: tests/browser/tweet_bookmarklet.mjs, tweet_image_import.mjs (TWEET_UI=1 for theme/paint checks; TWEET_EDGE=1 for real download-timeout recovery), existing bookmarklet copy checks, image preparation/transport/browser checks and affected PHP composer/publication tests.
Evidence limits: Local Chromium fixtures exercise source selection and signed publication; a real public photo-host fetch/preparation passed. Live X tweet pages were inaccessible in the implementation environment, so live page markup/CSP execution remains unverified. Physical devices, qutebrowser and a full application-suite run were not verified by this cycle.
