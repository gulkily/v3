Material risks and early checks for the selected slice:
Names: local signed profile-name history can differ from the name encoded in public armor. Impact: misleading publication and unintended username grouping. Before allowing publication, compare the local name with the derived destination registration name. Refuse/report mismatches until an identity-history transfer is separately approved; do not fabricate a rename or silently discard the difference.
Retirement: publishing a locally retired key to a destination without its retirement record could revive an unwanted identity. Identify and exclude local retired keys; treat destination retirement as refusal, not success. No retirement record transfer or retirement redesign in this slice.
Authority: public registration is neither proof of private-key possession nor approval, operator status or message access. Verify approval state stays unchanged and display the destination's actual name/state; no automatic approvals or seeds.
Existing identities: duplicate registration is an error, not an idempotent success. Preflight by fingerprint, distinguish retirement and policy refusal from absence, and read back after an uncertain response. Never infer absence from timeout, HTML, authentication failure or generic non-200.
Partial acceptance: retain per-key results and allow rerun without replacing existing records. Changed source bytes or a changed destination need a fresh preview. Do not call a lost response a definite failure or regenerate identities.
Retired/changed public armor: a fingerprint match is a useful identity match, not proof every public armor byte/subkey is equal. Define this slice as missing-identity publication; existing identities are skipped, not updated. Surface mismatched local profile metadata; do not claim key-update synchronization.
Destination and credentials: require an explicit destination and clearly bind preview and publication to it. Preserve public/private instance access policy; no embedded production defaults, credential transfer, unsolicited peer discovery, production requests or new authentication bypass.
Source records: read only canonical public-key/identity/name/retirement evidence needed for classification, using existing models. Reject private-key armor or other private material before preview/network work, even if it appears in a public-key directory. Verify outgoing payloads contain only the selected public key. No private keys or private-message stores are transmitted or logged.

Step 3 planning decisions (2026-11-22T21:43:30+00:00):
Approval: Maintainer said "approved step 2". No enhancement or scope change; Step 3 planning only. Step 1/2 text stays unchanged.
Ordinary interface: publish-keys accepts an explicit HTTP(S) destination, normal --repository-root override and a timeout. Default invocation previews only. --plan=FILE writes a local human-readable plan. --publish=FILE plus one or more explicit --key fingerprints publishes that selection; there is no automatic all-keys publication or repeated confirmation prompt. Unknown/empty options fail before remote writes. Existing import behavior is untouched.
Plan record: Use the existing Key: value text convention and GenericTextRecordParser, with a destination, canonical source-root binding, selected fingerprint/name/armor digest and name/retirement evidence digests. Bind the exact public payload to its source bytes. Require a new preview after relevant source/destination/selection changes. Public metadata only; never include private keys, cookies or credentials. This is local review data, not a signed authority record. Document its supported shape with the command; do not introduce JSON or a new canonical server record.
Source selection: Walk only canonical public-key/identity/name/retirement paths. Use IdentityBootstrapRecordParser, ProfileNames and KeyRetirement; do not trust an unrefreshed derived display name or scan browser/agent storage. Reject paths escaping the chosen root, ambiguous/unassociated/malformed keys and private material. Use the established retirement model; uncertain evidence is a refusal, not active status.
Strict inspection probe: Generated one disposable Ed25519 fixture in a temporary isolated GPG home, outside the repository. Public export showed colon record pub. Secret export showed sec. Relabeling secret armor as PUBLIC KEY BLOCK still showed sec. Appending secret armor after a public block showed pub,sec. All commands exited zero. Therefore armor labels and successful inspection are insufficient to enforce public-only payloads. No key bytes printed; fixture/keyring removed.
Strict inspection decision: Extend OpenPgpKeyInspector with an opt-in public-only method returning the existing fingerprint/username metadata. Validate one supported public block and all GPG public/secret record classes; reject secret primary/subkeys and extra payload. Keep inspect() and legacy callers unchanged. Test both ordinary private armor and secret packets under a public label before enabling any destination request.
New helper rationale: The archive downloader only supports fixed archive paths and follows redirects; it is not a profile/registration client. scripts/publish_text.php contains top-level CLI/signing behavior, not a safely importable generic client. Add a bounded project-owned public-key publisher and narrowly scoped destination helper under src/ForumRewrite/Support/, reusing platform stream conventions, existing URL validation and canonical parsers. Do not copy a second key parser, registration writer or general HTTP framework.
Planned helper boundaries: collect(root) returns checked canonical identities; profile(destination, fingerprint) returns typed present/missing/refused/unknown metadata; preview(inventory, destination) produces the text plan; publish(plan, fingerprints) revalidates and returns per-key outcomes. Keep data and parsing in the publisher; the scripts entry handles arguments/output/exit status. These are proposed helper contracts, not new server API signatures.
Transport: Validate the explicit base URL (HTTP/HTTPS, no userinfo/query/fragment); preserve a supported base path. Bound request deadlines and response size, retain TLS peer checks, and reject redirects so publication cannot drift to another host. Read get_profile as its existing Key: value protocol and link_identity as its existing key=value protocol; canonical local plans/output remain Key: value. Do not turn HTML, a generic 404, timeout, refusal or malformed profile into missing status. Use no borrowed browser sessions or cross-site credentials; restricted targets fail with an actionable next step.
Publication: Submit only public_key to link_identity; do not send local bootstrap anchors. Compare destination read-back identity/name and retirement state. Existing fingerprints are skipped rather than updated; conflicting name/retirement metadata is reported. On an uncertain POST, query the exact identity before retry. Failure of read-back leaves an unknown outcome with retry guidance; success does not imply possession, approval, operator status or message access.
Results: Print a concise human-readable per-key result and summary. The reviewed plan remains available; completed keys are discoverable remotely, so an interrupted run can use the same selection without a second transaction journal. Selected unknown/refused/conflicting keys produce unsuccessful status while confirmed/already-present keys remain distinguishable. Do not overwrite existing identities or approvals to repair a failed run.
