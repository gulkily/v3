ZenMemes redesign mockups

Eleven of the 53 page templates, about 20%, chosen as the screens people use most: reading the board, reading and replying to threads, posting, profiles, the member list, account setup, private messages and the tools launcher.

The focus is wording, arrangement and process flow. The visual skin is deliberately neutral, because themes restyle it. Each page shows desktop and phone frames, a light/dark switch, notes and a before screenshot.

Themed set · “Living Sky”

A ZenMemes default skin applied to six of the screens above, as one stylesheet layered on the same structure (zen/zen.css). The whole screen is a moving sky: a dawn gradient in light mode, and deep space with drifting nebulae, twinkling stars and the occasional shooting star in dark mode. Each sky is tinted by whoever the screen is about. Content floats on frosted glass. People are glowing planets in their own colors, icons are drawn in color, and one ember-to-violet gradient marks every primary action. Each page has a Base / Living Sky / Ma switch for comparison.

Second theme · “Ma” (間), the meaningful empty space

The same six pages, designed as if by a panel: Kenya Hara, Tadao Ando, James Turrell, teamLab, Tyler Hobbs, Ikko Tanaka and Shigeo Fukuda. Paper, space and a quiet serif. One shaft of light crosses each page, and the page is lit from above in the color of whoever it is about. Petals fall with the community’s activity. Keys are drawn as flow fields, people are flat geometric shapes, and the logo is an ensō that is also a calm face, next to a vermilion seal. No blur anywhere. The pages open in Ma.

Ma is Kyoto by day and Shinjuku by night: dark mode turns cyberpunk. The seal becomes a neon sign, rain falls instead of petals, keys glow like neon tubing, account cards read like ID chips with real key data, incoming messages visibly decrypt, and glitches appear only on failures.

Wording

  • Name things the way readers do (“Back up account”), not the way the system works (“Download text backup”).
  • Short metadata (“ilyag · Sep 6”). Exact times are available on demand.
  • Remove copy that restates a control. Keep warnings about privacy and data loss next to the decision they affect.

Arrangement

  • One primary action per screen.
  • Lists separated by hairlines instead of a box around every item.
  • Rare and operator-only controls go behind ··· or Advanced.

Flow

  • No native prompt() or confirm() dialogs. Decisions happen in the page.
  • Slow work (key generation, decryption) starts before the user asks for it.
  • Every failure says what happened and offers the fix the user can apply.
