# UI copy audit checklist

Reduce reading required to complete ordinary forum tasks. Favor removing text over rewriting or relocating it, relying on an intuitive, explorable interface. For every finding below, first consider deleting the explanation; suggestions to shorten text or move it into help are fallbacks only when users need information the interface cannot communicate. Keep material consequences and recovery actions beside the affected control.

Source review dated October 17, 2026 covered page templates, shared partials, and selected first-party browser messages. These are copy and presentation findings; rendered layouts and every runtime state have not been reviewed. Product copy is unchanged. Items below remain open.

## First fixes

- [ ] **Invite generation** — [invites.php](../../templates/pages/invites.php), opening paragraph. Four sentences mix sponsorship, link possession, expiry, existing-account access, and policy evaluation before a simple form. Lead with a short warning such as “Anyone with this link can use the invite. Share it only with the intended recipient.” Move policy mechanics into help; retain expiry with the generated result and show existing-account access consequences where that situation is known. Check generation and acceptance together before removing any warning.
- [ ] **Public backup downloads** — [instance.php](../../templates/pages/instance.php), introductory paragraphs and final five paragraphs. Repeated explanations of public records, restoration, exclusions, and repository/index differences obscure the downloads. Keep a short scope statement and the instruction to download images with the repository; consolidate exclusions and restoration details under one expandable section. Preserve the distinction between public-content and complete-instance backups.
- [ ] **Activity security notice** — [activity_security_notice.php](../../templates/partials/activity_security_notice.php). A four-sentence notice combines current policy, key grants, non-revocation, and historical uncertainty. Keep the current policy concise; move interpretation details behind help, retaining the non-revocation consequence at any policy-changing control. Check both activity views that reuse this partial.
- [ ] **Profile diagnostics** — [profile.php](../../templates/pages/profile.php), self-profile block and bootstrap metadata. “Account-aware bootstrap context,” the cookie hint, internal setup artifacts, and route metadata expose implementation concepts during profile viewing. Put diagnostics in a technical section and remove redundant “This is your profile” / “Your current browser identity matches this profile” wording.
