## Stage 2 - Required runtime capabilities
- Changes: added a standalone pre-application probe for PDO, PDO SQLite opening in memory, mbstring and its used functions, server process/lifecycle functions, PHP child execution, PHP shell execution, and Git execution from PHP. Both entry points share aggregated checks and selected-CLI/configuration recovery guidance; Ubuntu 24.04/PHP 8.3 extension instructions remain manual. Checks never inspect or alter application databases or repositories.
- Verification: both shell regression scripts and PHP 8.1 probe syntax passed; real PHP 8.1/8.3 healthy diagnostic reports passed. A real PHP 8.3 matrix removed PDO, PDO SQLite, and mbstring, and disabled `proc_open`, `exec`, and `mb_ord`: both commands returned 1 with actionable guidance and no log, repository, database, or fatal error. Restored SQLite/PHP/Git execution returned 0 without application state changes. `git diff --check` passed.
- Notes: missing software and disabled PHP functions have distinct guidance; a standalone `sqlite3` executable does not satisfy PDO SQLite. PHP-dependent probes are skipped when PHP/version prerequisites are unavailable. Terminal and normalization warnings follow in Stage 3; persistent integration coverage follows in Stage 4.

## Stage 3 - Optional degradation and reliable shutdown
- Changes: added nonblocking warnings for intl, PCNTL functions/constants, terminal `shell_exec`, and `stty`; guarded terminal sizing/restoration and kept plain fallback logs. The Bash launcher supervises the PHP wrapper through a control pipe so SIGINT/SIGTERM and launcher exit permit child cleanup without PCNTL. PHP cleanup is registered for error exits and uses bounded termination, with forced child termination if graceful termination fails. Missing intl guidance explains existing combining-mark rejection.
- Verification: shell regressions and Bash/PHP 8.1 syntax checks passed. Real PHP 8.3 lifecycle checks covered 20 combinations: normal runtime, missing PCNTL functions, disabled `shell_exec`, both disabled, and missing `stty`, each with terminal/redirected output and SIGINT/SIGTERM to the foreground process group. Every case served an HTTP request, wrote plain logs, exited successfully, and left no listener. PHP 8.1 Unicode policy/risk and logging tests passed: 25 run, 0 failures. Required-failure matrix remained passing; `git diff --check` passed.
- Notes: terminal cosmetics stay optional. Lifecycle control needs Bash (already the launcher interpreter), not a new installed signal utility. The test packages include PCNTL statically, so absent support was exercised by disabling its functions. Runtime warnings do not change diagnostic success status.

## Stage 4 - Repeatable end-to-end recovery verification
- Changes: added `tests/local_server_dependency_runtime_test.py`, a Python-standard-library harness using real PHP, isolated projects/configurations, state snapshots, installer sentinels, HTTP thread/reply creation and reads, PTY/redirected output, and launcher/process-group signals. Expanded shell coverage for unreadable PHP identity. Corrected an existing Unicode inspector test that assumed intl was absent; it now verifies both normalization outcomes, with a matching policy regression.
- Verification: PHP 8.3 integration passed seven required-capability failure cases in both entry points and 20 HTTP read/write/log/shutdown combinations. PHP 8.1 integration passed eight failure cases (including disabled `escapeshellarg`), healthy/restored and corrupt-database readiness reports, unattended installer sentinels, and the same 20 lifecycle combinations. PHP 8.3 targeted bootstrap/write/Unicode/logging suite: 29 passed. PHP 8.1 Unicode/logging suite: 26 passed. Both shell scripts, Bash syntax checks, and `git diff --check` passed.
- Notes: every real-runtime failure preserved the isolated project's complete file snapshot; dependency reports do not validate application checkout/database health. Tests require Python 3 for HTTP/PTY orchestration and PHP CLI with its normal required extensions; neither is installed by the tests. Shared-extension removal cases explicitly skip statically compiled modules. Existing Unicode application behavior remains unchanged.
