# Feedback items

Purpose: Keep each requested outcome from site feedback as one file with a permanent ID, kind, workflow state and sources, so its status can change and be referenced without hunting through dated summaries.
Scenario: After an import, triage finds a new post asking for a summary field and writes `docs/feedback/items/PF-20261103-F01.txt` with the request and the post's URL. A second post asking the same thing adds its URL to that file's `Sources:` instead of creating another item. When work lands, the item's `Workflow` changes to `done` in the same commit. `./v3 feedback check` fails on a malformed file and lists any post shared by two items for review.
Sources: [record format](../specs/feedback_item_record_v1.md), [item](../../src/ForumRewrite/Feedback/FeedbackItem.php), [check](../../src/ForumRewrite/Feedback/FeedbackItemCheck.php), [command](../../scripts/feedback.php), [tests](../../tests/FeedbackItemCheckTest.php).
Boundary: Proposed in [feedback work restart](../plans/feedback_work_restart/feedback_work_restart_step3_development_plan.md); as of Stage 1 only the format and check exist. The index, seeded items and triage procedure arrive in later stages. Site members cannot change status; items live only in the repository.
