# Site tagsets record

Name: Site tagsets record
Purpose: Let operators change and add tagsets from the site, without a code change or a deploy.
Scenario: An operator opens Tools → Tag Unlocks, taps Edit, and changes the same `Key: value` text as `resources/tagsets.txt`. Preview shows the rules, any errors by line, and the threads whose marks would lose their buttons; Save stays off until the current text previews without errors. Saving signs one change record in the browser, and one commit writes it with `records/instance/tagsets.txt`, which then replaces the shipped file entirely. Post states are recomputed and generated pages cleared in the same request. Reset to default signs a reset record and removes the site file.
Sources: [loader and checks](../../src/ForumRewrite/Support/Tagsets.php) (`check`, `forRepository`, `active`), [write](../../src/ForumRewrite/Write/LocalWriteService.php) (`prepareTagsetsChange`, `finalizePreparedTagsetsChange`), [state recompute](../../src/ForumRewrite/ReadModel/IncrementalReadModelUpdater.php) (`applyTagsetsWrite`), [affected threads](../../src/ForumRewrite/Tools/MarkedPostsQuery.php) (`losingButtons`), [page](../../templates/pages/tag_unlocks.php), [editor script](../../public/assets/tag_unlocks_edit.js), [record spec](../specs/tagsets_change_record_v1.md).
Boundary: Operators only; other keys see the page read-only. A rule change never rewrites marks: they stay stored, and a mark whose tag is no longer a state tag stops setting a state until the tag returns. New tags show their name as written on the button; per-tag labels are not supported. A thread page already saved for offline reading keeps its old buttons until it is next fetched; the server refuses a stale tap with its usual message.
Verification: tests/TagsetsTest.php; tests/EditableTagsetsTest.php; tests/browser/editable_tagsets.mjs.
