# Shared composer

Purpose: One partial renders every writing form (new post, compact board and QDB add, reply) so field names, signing, drafts, Outbox and attachments behave the same everywhere, while each placement chooses only what it shows.
Scenario: On the New post page a member sees the body first, then the Post row with the ··· menu, then the optional Title and the tags (and event, when enabled) below it. On a phone the body starts at the compact form's height and nothing is reserved between it and Post, so when the keyboard opens both stay on screen; long drafts scroll inside the body. The paned board's New Thread dialog renders the same full form. The board, board list and QDB add render the compact form (body and Post only, Title and tags hidden). Replies render body and Post reply, with the phone reply docking on top where enabled.
Sources: [the composer partial](../../templates/partials/composer.php) (order and modes), [new post options](../../templates/partials/thread_compose_form.php), [reply options](../../templates/partials/reply_form.php), [compose styles](../../public/assets/compose.css) (phone rules under 640px), [composer browser test](../../tests/browser/composers.mjs) (order assertion), [layout stability test](../../tests/browser/compose_layout_stability.mjs) (`--phone-fit-only`: 13 themes at phone and desktop sizes).
Format: the ··· menu holds a Markdown box (unticked by default; `markdown_detect.js` ticks it when the draft looks like Markdown until the author sets it by hand; unticked posts are plain) and a Formatting help link; signed, unsigned and Outbox submissions all carry the choice as `body_format` ([post body formatting](post_body_formatting.md)).
