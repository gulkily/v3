# Tools launcher

Purpose: One list decides which tools exist, their order and their grouping, so the /tools/ page and the Tools bar inside every tool show the same tools and never drift apart.
Scenario: A reader opens Tools from the main navigation and sees one card: five groups by who uses the tools (Your device, Reading, Community, Developer, Operator), each of the tools once as a button (24 with every flagged tool listed: the usage tools, History, Import and Backlog show only while their flags are on). With all 23 listed before History was added, every tool is in view on a 1280×720 desktop in the default themes and most others on zenmemes; Bubblegum, Engagify, Spearmint, Arena, Zalgo and Underground need a little scrolling, and Word97 and Midnight miss by under 10 px. Opening a tool shows a Tools bar with the same tools in the same order, the current one marked and a divider at each group boundary. Full-page tools (Activity, Forte, Offline Reading, Platform Docs, Backlog) carry a ↗ marker in the bar and have no bar of their own. Backup leaves both lists when text and image backups are both off, and Usage Log and Usage Reports leave them while the Usage reports flag is off ([usage reports](usage_reports.md)). History, under Your device, shows only while the Visit history flag is on ([visit tree](visit_tree.md)). Developer is for people and agents who change the software, as opposed to the operator who runs this site: it holds Platform Docs and, only while the Backlog flag is on, Backlog ([backlog view](backlog_view.md)). Tools that act on this instance and are operator-gated (System status, SQLite Viewer, Feature Flags, Deploy) stay under Operator. The server HTML is the same for every viewer; tools that refuse a visitor refuse on their own page. Account is not a tool and lives in the main navigation.
Sources: [registry, groups and bar order](../../src/ForumRewrite/Tools/ToolsPageSupport.php) (`groups()`, `registry()`, `navOptions()`), [launcher page](../../templates/pages/tools.php), [Tools bar](../../templates/partials/tools_nav.php), [controller](../../src/ForumRewrite/Http/ToolsPageController.php), [launcher styles](../../public/assets/tools.css), [registry test](../../tests/ToolsRegistryTest.php), [site and theme matrix](../../tests/browser/tools_launcher.mjs).

Theme hooks: each tool item and bar link carries `data-tone` (a stable key from the registry) and each group heading carries `data-shape` (the group key). Icon themes key their glyphs to the link's `href` and the heading's `data-shape`; see [theme navigation icons](theme_navigation_icons.md). Bookmarklets reuses the `tool-launcher-button` class for its own list, so group and grid rules are scoped to `.tools-launcher-page` and do not reach it. The registry carries no per-tool description; the launcher shows labels only.
