# Photo details

Purpose: Let a poster share when, where and with what camera a photo was taken, only when they choose to, as readable signed text.
Scenario: A member attaches a camera photo. Under the preview, a collapsed "Photo details" row appears only if the photo carries metadata. Opening it lists Camera, Lens, Exposure, Taken and Location, each with its value and all unticked; Location adds "Shows where this photo was taken." The member ticks Camera and Taken and posts. The post page shows them under the image behind a closed "Photo details" row that opens on tap (a single detail stays visible without the row; the offline reader matches), and the closed row's summary names them while composing, like Options. A failed reply retries with the same choices.
Format: ticked details are lines directly after the `Image-v1:` line in the signed body, for example `Photo-Camera: Apple iPhone 15 Pro`, `Photo-Exposure: 1/120 s · f/1.8 · ISO 80`, `Photo-Taken: 2026-11-14T16:12:08-05:00`, `Photo-Location: 42.353600 -71.116700`. Only the five labels count, at most 120 characters each; a `Photo-` line anywhere else is ordinary text.
Sources: [EXIF reader](../../public/assets/image_prepare.js) (`photoDetails`), [checklist](../../public/assets/image_upload.js) (`renderPhotoDetails`, `chosenLines`), [partial](../../templates/partials/image_compose_fields.php), [signed lines](../../public/assets/browser_signing.js) (`imageSignedFields`), [parsing and display](../../src/ForumRewrite/Images/ImageReference.php) (`photoDetails`), [card](../../src/ForumRewrite/View/MediaEmbedRenderer.php), [offline mirror](../../public/assets/offline_reader.js), [tests](../../tests/browser/image_photo_details.mjs), [plan](../plans/image_metadata/image_metadata_step3_development_plan.md).
Boundary: The uploaded image file never carries metadata; the browser redraws it. Nothing is ticked by default, so ignoring the row posts exactly what was posted before. Location is never pre-ticked. iPhone Safari may remove location before the page sees the photo, so that row can be missing. `frm.py` does not attach photo details yet, and details cannot be edited after posting. RSS and the text API show the lines as plain text.
