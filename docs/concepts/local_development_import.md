# Local development import

Purpose: Make a fresh local instance explorable and bring public content into it through the browser.
Scenario: Run `./v3 start`, open its loopback homepage, browse sample threads or documentation, then import from the prefilled production source. Import returns at once: the card lists the import's steps with counts, an elapsed timer, the time since the last update and the time left, while other pages keep loading. Leaving and coming back shows the same progress. The card ends in a line of counts and Browse imported threads, which opens the existing All view. A failed download shows its reason and retains the source for retry; a pending import journal offers Resume. The existing CLI owns validation, conflict handling, public-content exclusions and publication.
How it runs: the page queues the same `instance_import` task as Tools → Import, recorded as requested by `local-development`, and the task worker runs it. `./v3 start` runs that worker; with `--no-worker` the page starts one, and says so with the command and Try again if none starts within 15 seconds. Without JavaScript the page reloads itself every 5 seconds while an import runs. The result on the card is read from the import's own output.
Boundary: Controls require the development launcher marker, PHP's development server, a loopback peer and Host, no proxy headers, and a valid token plus origin checks for every POST, including the page script's status requests. Deployed servers and remote clients retain normal pages. Existing query-bearing root URLs retain their board behavior. Imports merge public content rather than mirror or delete local content. A running import cannot be stopped from the page.
